# פרומפט להקמת המאגר באמצעות ChatGPT Work

פתח את הקובץ `github-workflows.zip` שצירפתי בשיחה או שהעליתי ל־Work. צור בחשבון GitHub האישי `Nisan-Sinai` (לא Organization) מאגר חדש בשם **`github-workflows`**.

1. המאגר צריך להיות **Public** כדי ש־Reusable Workflows ממנו יוכלו לשמש גם מאגרים ציבוריים וגם פרטיים. בדוק שהקבצים אינם כוללים סודות או רשימת שמות של מאגרים פרטיים.
2. העלה את כל קובצי החבילה ללא שינוי, כולל תיקיית `.github`, ענף ברירת המחדל `main`. אל תעתיק קובצי מערכת כגון `__pycache__`.
3. הרץ את בדיקות המאגר `python scripts/validate.py` ו־`python -m unittest discover -s tests -v` (דרוש `PyYAML==6.0.3`), ולאחר הדחיפה ודא שבדיקת GitHub Actions `Hub / validate` ירוקה.
4. הפעל הגנת `main` של המאגר המרכזי עצמו, עם PR חובה, בדיקת `Hub / validate`, ללא Force Push ומחיקת ענף. אם פעולה מצריכה אישור משתמש — בקש את האישור בממשק GitHub. אל תחליש הגנה או תעקוף בדיקה.
5. הרץ דוח מלאי לקריאה בלבד באמצעות `Public policy drift report`; דווח האם יש מאגרים שטרם הוגנו או שעדיין אין בהם Dependabot, מבלי לשנות אותם.
6. **אל תפתח/תמזג PRs בכל 13 המאגרים הקיימים ואל תשנה את ההגנות שלהם בשלב זה.** הכנת אינטגרציות תהיה בשלב שני, אחרי אישור מפורש לכל מאגר. שמור את כל CI/Vercel/Supabase/Playwright/Dependabot הקיימים בלי להסיר דבר.
7. דווח בסיום על קישור המאגר החדש, ה־commit SHA המלא, תוצאות הבדיקות, והאם הגנת `main` של המאגר החדש אכן הופעלה. אל תציג הצלחה אם אחת הפעולות לא בוצעה בפועל.

המערכת נועדה להיות מקור מרכזי **אופציונלי** לכל סוגי הפרויקטים שלי, כולל `main`, `dev` ו־`master`, ללא תלות ב־Organization. אל תפעיל כתיבה אוטומטית לניהול Branch Protection ללא הרשאות ואישור מפורשים שלי.
